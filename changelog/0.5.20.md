# 0.5.20 - 2026-11-10

One version, one number. Every statement in the tree that named a version now reads the value
`Directory.Build.props` declares, so the exe, the wrapper manifest, the server manifest and the npm
package cannot disagree again, and a test fails the build when one of them drifts.

The tool surface changed shape in several ways at once. Every tool carries a title, every failure
carries a code from one table, twelve collection tools state the cap they were held to, twelve
wrapper records publish an output schema, and the two placement tools take one `placement` object
while the flattened arguments keep working for this version.

### Added

- `error_codes`, which returns every code the surface can raise with its meaning.
- `file_extract`, which writes one archive entry to `out_path` as raw bytes through the write gate.
- An output schema on twelve wrapper record tools, derived from the return type.
- A title on all 277 tools.

### Changed

- The MCP reference carries family, parameters, result type, error codes and hints for every tool.
- `file_get_text` reports the encoding it used and refuses a lossy decode unless `allow_lossy` is set.
- `quickstart` returns `{items, count}` rather than a bare array.
- `version_info` carries the product id, the protocol revision and the SDK version.
- `place_unit` and `place_doodad` take a `placement` object, with the old arguments still accepted.

### Fixed

- A write can no longer reach a symbolic link, and `target_set` refuses an existing settings file
  without `overwrite`.
- Closing stdin no longer abandons a call that was already read. The drain counts pending messages
  rather than dispatched calls and holds the quiet reading for 250 ms.
- A schema failure names the tool and the missing argument.
- A call that arrives before any `tools/list` is answered rather than refused as unknown.
