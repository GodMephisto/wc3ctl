# 0.5.41 - 2026-11-16

The wrapped doctor moves to 2.3.2 and the wrapper stops carrying a hand written copy of what it can
do. The doctor has answered `schema --json-schema` since 2.2, a versioned description of every
command, option and result key it defines, so the wrapper reads that rather than a comment naming
the release its lists were transcribed from.

The pin mattered more than the version number. 2.3.2 carries `names.npz`, a name dictionary that
recovers the entries a protected archive hides, so on the map this was measured against it reported
21 model paths that resolve to no file where 1.7.6 reported 96, and it returned a verdict of
"probably" on a map 1.7.6 called impossible. Two builds that answer the same question differently is
the whole reason the pin is by sha256 and not by version.

The option surface grew with it. The steps and extras a fix can be asked for now include
`remove-game-files`, `remove-game-copies`, `fix-requirements`, `fix-model-paths`, `fix-fdf`,
`null-handles`, `fix-attributes`, `console-sides`, `minify`, `strip-comment-blocks`, `slk-objects`,
`fix-graphics-modes`, `shrink-models`, `shrink-models-lossy`, `shrink-lossy` and `translation-keep`.
`portraits` now also takes a value, `stamp` or `upgrade`, and a value is only accepted for an option
whose values the wrapper enumerates, so `translation=<file>` and `lobby-image=<picture>` stay out.

### Added

- `doctor schema` on the CLI and `doctor_schema` over MCP, which return the installed doctor's own
  `--json` contract unchanged.
- `qol` and `cheatpacks` as read-only doctor reports, through `doctor inspect` and `doctor_inspect`.
  `script` joins them, so the map's own script is a read rather than an `extract` to disk.

### Changed

- `PinnedBuilds` carries 2.3.2 by sha256 beside 1.7.6, so a machine with the older build installed
  keeps working and the newest folder wins when both are present.
- `doctor_fix` takes an option with a value as `name=value`, validated against the enumerated set.
  A `no-` prefix and a value on the same option is refused rather than passed through.

### Notes

- The MCP server still refuses any map over 92,274,688 bytes with `PRF09_MEMORY_BUDGET`. A map
  above it is repaired through the CLI, which has no such cap.
