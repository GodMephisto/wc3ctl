# 0.5.46 - 2026-11-26

- `SixLabors.ImageSharp` is gone. It was a direct reference in `Wc3.Render` only and reached
  `Wc3.Mcp` and `Wc3.Commands` through project references, so removing that one reference takes it
  out of the solution, and `War3Net.Build` 6.1.1 does not depend on it.
- `SkiaSharp` 3.119.4 replaces it, MIT with no licence gate, moved in both `src/Wc3.Render` and
  `tests/Wc3.Tests` in the same commit because the two project files have to agree or NU1605 trips.
  Every ImageSharp release from 3.2.0 up is under the Six Labors Split License and a Release build
  without a key fails outright, so the old pin could not move.
- `SafeImages` sniffs the magic numbers itself now, since SkiaSharp cannot be told to skip metadata.
  A PNG, JPEG, BMP or GIF signature is recognised before a decoder exists, TGA carries no magic
  number so it is recognised by its header instead, and its second byte has to be zero because those
  four signatures all put a non-zero byte there.
- PNG ancillary chunks and JPEG APP1 through APP15 and COM segments are stripped before a decoder
  sees the bytes, which is the containment the advisories needed and the reason the code path had to
  survive the library change.
- SkiaSharp has no TGA encoder, so uncompressed and RLE 24 and 32 bit TGA are written by hand, with
  a test file per variant.
- 16 bit grayscale heightmaps keep their own exact path, because resampling them through a general
  encoder changes the file and the heightmap tests compare bytes.
- `THIRD-PARTY-NOTICES.md` loses its ImageSharp section and gains a SkiaSharp one, MIT text taken
  from the package's own `LICENSE.txt`, with the note that SkiaSharp bundles Skia under BSD-3-Clause
  and those notices travel in the NativeAssets package. `CREDITS.md` names SkiaSharp in the table.

Version 0.5.46.
